# Tutora constitution

These rules apply to every spec, plan and pull request. A change that breaks one needs an amendment to this file first, agreed with Victor.

## Product

1. **Offline first.** Every feature works with no network. The only network call in v1 is the optional daily USD/BRL rate fetch, and it never blocks a screen.
2. **The teacher's data stays on the phone.** No accounts, no backend, no analytics. Data leaves the phone only when the teacher shares or backs it up.
3. **Nothing is lost silently.** Destructive actions (delete, restore, migration) are confirmed or preceded by an automatic copy of the database.
4. **Language and currency are independent.** Changing one never changes the other.

## Code

5. **TypeScript strict** everywhere. No `any` without a comment explaining why.
6. **Layers point down:** screens → state → use cases → domain / repositories / adapters. Screens never import from `data/` or run SQL.
7. **The domain core is pure.** `src/domain/` imports nothing from React, Expo, React Native or SQLite. Time comes in as a `now()` argument.
8. **Money is integer minor units** (`cents`) with its currency. No floating-point money, ever. Rounding is half away from zero, once per result, in `domain/money.ts` only.
9. **FX rates are integers with 4 decimals** (`usd_brl_e4`), always stored as USD→BRL, and saved on every lesson and payment.
10. **Instants are UTC ISO 8601 text** with milliseconds and `Z`. Local days, weeks and months are computed in the device time zone and converted to a UTC `[from, to)` range.
11. **Every write is a use case** that runs in one SQLite transaction, then calls adapters and invalidates queries.
12. **Migrations only go forward**, are generated by `drizzle-kit`, and are tested against a database seeded at the previous version.
13. **Styling is Tailwind through NativeWind.** Colors are only used through semantic theme classes (`bg-primary`, `text-earnings`), never hex values in components.
14. **All user-facing text goes through i18n** with keys present in both `pt-BR.json` and `en.json`. Money and dates are formatted with `Intl` at the edge.

## Process

15. **Spec first.** Each feature has `spec.md` (what and why, no technology), `plan.md` (how) and `tasks.md` (ordered steps) before code.
16. **Every acceptance criterion has a test** whose name contains its id (for example `AC-001-3`).
17. **One spec per branch and pull request.** CI (type check, lint, tests) must pass before merge.
18. **Performance budget**, checked on a mid-range Android phone before each release: cold start to Today under 1.5 s, tab switch under 300 ms with a year of data, lists at 60 fps.
19. **The release signing key is never lost.** It lives outside the repo, in a password manager plus an offline copy.
