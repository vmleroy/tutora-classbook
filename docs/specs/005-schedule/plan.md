# Plan 005: Schedule

Architecture reference: [`docs/architecture.md`](../../architecture.md), sections "Database schema and migrations", "Money and time" (time rules) and "State management and data flow". Mockups: [`Main`](../../mockups/Main.dc.html), [`Schedule`](../../mockups/Schedule.dc.html), [`AddLesson`](../../mockups/AddLesson.dc.html) (Agendar mode) and [`EditLesson`](../../mockups/EditLesson.dc.html) (date, time, duration, value, scope, notes, Remove).

## Approach

- **Domain.**
  - `src/domain/recurrence.ts`: `occurrences(rule, from, to)` lists a rule's local dates (weekly or every 14 days from `startsOn`, up to `endsOn`, minus skipped dates). `localToUtc(date, time, zone)` and `utcToLocal` use `@date-fns/tz`, so a class stays at its wall-clock time whatever the time-zone rules (AC-005-9).
  - `src/domain/schedule.ts`: `lessonValue(lesson, place, link, student|group)` returns the hand value if set, else the resolved price (004) for the duration, plus travel. `dayExpected(lessons)` returns `{ cents, salary }`. `layoutDay(blocks)` places overlapping classes in side-by-side columns. `greeting(hour)`, `nextLesson(lessons, now)` and `weekOf(date)` (Monday first) round it out.
  - `date-fns` and `@date-fns/tz` are plain JS, allowed in the domain.
- **Data.** Migration `0002` adds `schedule_rule`, `rule_skip` and `lesson` (see Data). Repos live in `src/data/repos/scheduleRepo.ts`. Reads join place, student or group, and the student's link, so the domain can price each class.
- **Use cases** (`src/usecases/schedule.ts`):
  - `scheduleLesson`: one-off, or a rule plus its first 8 weeks.
  - `fillSchedule(today, zone)`: idempotent, run at start-up and whenever the app comes back to the foreground.
  - `editLesson(id, change, scope)` and `removeLesson(id, scope)`, where scope is `'one' | 'following'`.
  - `lastTravelFee(studentId, placeId)` for the suggestion.
  - The device zone comes from `Intl.DateTimeFormat().resolvedOptions().timeZone`, passed in.
- **Series edits.**
  - **"Só esta aula":** updates the lesson and sets `is_detached`, so filling never touches it again. Removing only this class deletes it and adds a `rule_skip` for its occurrence date.
  - **"Esta e as próximas" from occurrence D:** ends the old rule the day before D and creates a new rule from the edited class onward (its new weekday, time, duration, value and travel). Scheduled, non-detached lessons of the old rule from D on are deleted and the new rule fills them. Detached lessons stay (Victor). Removing this and following ends the rule and deletes its scheduled lessons from D on, detached ones included, since the series is gone.
  - Lessons that already started never change (AC-005-15).
- **Prices follow** (AC-005-16): a scheduled lesson stores no price, only a hand value when typed. Its value is resolved on every read, so price changes reach it. 006 freezes `earned_cents` when a class is done.
- **State.** `src/state/schedule.ts` holds `useLessons(fromIso, toIso)`, `useNextLesson()` and `useScheduleActions()`. Writes invalidate `lessons` (and `places` / `students`, whose screens will show classes later).

## Data

Migration `0002`, generated by `drizzle-kit`:

| Table | Columns |
| --- | --- |
| `schedule_rule` | id, student_id / group_id (exactly one, CHECK), place_id, weekday (1 = Monday … 7), start_time `HH:MM`, duration_min, repeat (`weekly` / `biweekly`), starts_on and ends_on (local dates, `YYYY-MM-DD`; ends_on nullable, inclusive), time_zone (IANA), value_cents (hand value, nullable), travel_fee_cents (nullable, Casa do Aluno "varies"), generated_until (local date), created_at, updated_at |
| `rule_skip` | rule_id, occurrence_date; primary key on both; cascade |
| `lesson` | id, rule_id (nullable, set null on delete), occurrence_date (the rule date it came from; nullable for one-offs), student_id / group_id (exactly one, CHECK), place_id, start_at (UTC ISO), planned_min, status (`scheduled` for now; 006 adds the rest), value_cents (hand value, nullable), travel_fee_cents (nullable), is_detached, notes, created_at, updated_at. Unique (rule_id, occurrence_date) makes filling idempotent (AC-005-8). Indexes on start_at, (student_id, start_at) and (place_id, start_at). |

This departs from the architecture's `lesson` sketch: `rate_type` / `rate_cents` are not snapshotted while a class is scheduled (Victor's answer: prices follow). 006 adds `actual_min`, `earned_cents`, fees and the full status set. The architecture doc is updated to match.

## Screens and components

- `src/app/(tabs)/schedule/index.tsx` (Agenda):
  - month title, ‹ › weeks, WeekStrip with dots and today marked
  - Dia / Semana SegmentedControl, and the day header with "Previsto"
  - Dia: a 24-hour ScrollView with AgendaBlocks placed by `layoutDay`, scrolled to the first class or now
  - Semana: seven columns of blocks
  - an accent `+` in the header
- `src/app/(tabs)/today/index.tsx` (Hoje): greeting and date, a Próxima aula Card, "Aulas de hoje" with LessonRows, and an accent `+` in the header next to the gear.
- `src/app/lesson/` root stack:
  - `new` (Nova aula, Agendar mode)
  - `[id]/edit` (Editar aula: same form plus "Aplicar mudanças em", notes and Remover)
  - 006 adds `lesson/[id]` (detail) and the Registrar mode
- Form parts:
  - the student or group picker (SelectField plus a BottomSheet list with avatars)
  - place Chips (only linked places)
  - a date picker sheet (a month row, ‹ › weeks and a WeekStrip)
  - start time as a `TextField kind="duration"` limited to 23:59, in hh:mm
  - `DurationStepper` and `PriceStepper`
  - travel PriceStepper, Repetir Chips, and the scope SegmentedControl
- Design system: `WeekStrip` gets a `today` index (the day number in primary). AgendaBlock needed no change: the grid places each block in a positioned view, and its guideline now says so and drops drag (not planned). `TextField kind="duration"` doubles as a time-of-day field with `maxMinutes={1439}`.

## Test strategy

Lean: one Jest test per criterion.
- **Domain:** `src/domain/recurrence.test.ts` (AC-005-6, 7, 9) and `src/domain/schedule.test.ts` (AC-005-4, 16, 19, 21, 22, 23).
- **Use cases** on a migrated Node database: `src/usecases/schedule.test.ts` (AC-005-2, 3, 5, 8, 10–15).
- **Screens:** `tests/app/schedule.test.tsx` (AC-005-1, 17, 18, 20, 24, 25, 26).
- No Maestro.

## Risks

- **Time zones in Node tests.** Jest runs in the machine's zone. Tests pass an explicit zone (`America/Sao_Paulo`, plus one DST zone such as `America/New_York` for AC-005-9) and a frozen `now`.
- **24-hour grid performance.** It has at most a few dozen blocks; a plain ScrollView is enough.
- **Size.** This spec is as large as 004. Data and rules land first, then the form, then Agenda and Hoje.
